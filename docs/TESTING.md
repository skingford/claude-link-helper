# 验收与测试范围

## 自动化

运行 `npm test` 与 `npm run check`。

已覆盖：

- 精确按钮文字匹配、空格及零宽字符规范化、图片和可访问名称。
- URL 用户信息、域名后缀伪装、协议、端口、控制字符和非登录页面拒绝。
- Safe Links / Google 包装、嵌套上限、参数歧义、token 的 `+` / `%2B` / fragment 保真。
- `#token:base64载荷` 格式的 Gmail 正文识别与完整复制；全部使用虚构凭据。
- 同一目标去重、多个不同链接禁止复制、合法与未知候选混合时禁止复制。
- Gmail、Outlook、Proton、Tuta、Zoho、Yahoo、Fastmail、QQ、网易和通用正文结构。
- 隐藏与折叠邮件、草稿编辑器、引用旧邮件、Shadow DOM。
- 重复注入不重复 UI、DOM 变化后更新、点击时 token 改变、插入额外链接、复制失败。
- 弹窗成功/缺失/多链接/引用/扫描上限状态，以及权限错误、跨域 frame 失败时降级。
- 手动检测后显示弹窗复制按钮、点击时重新校验、绑定原文档、修订编号失效、多 frame 歧义、剪贴板失败重试；检测结果和页面 UI 中不泄露 token。
- 未适配邮箱仅检测并提供弹窗复制，不插入正文控件；带黑色背景的登录按钮容器、表格单元格和邮件整体结构在重复检测后保持不变，同时保留文档范围的多链接校验。
- Manifest / JavaScript 语法 / 资源完整性和运行时代码无网络、日志、持久化调用的静态检查。

DOM 单元测试通过 jsdom 模拟可见性。它们用于验证逻辑，不代表各邮箱当前线上 DOM 的完整快照。

## 浏览器验证

使用 ego-browser 驱动 Chromium，打开本地合成邮件测试页。已检查正文旁的真实按钮、复制后粘贴回读、动态状态切换、Shadow DOM 和同源内嵌邮件。生产脚本同时可注入隔离世界检查执行边界。

本次环境不提供 `Extensions.loadUnpacked` 自动加载能力，所以浏览器验证使用同一组生产内容脚本的测试页及隔离世界，不等于实际安装的扩展端到端认证。实际扩展的自动站点匹配、浏览器权限弹窗及各服务的真实登录邮件仍需安装后验证。

## 真实邮箱验收步骤

在每个目标邮箱分别执行：

1. 加载 `extension/`，刷新邮箱，打开自己申请的一封 Claude 登录邮件。
2. 核对助手位于对应邮件正文顶部；点击复制，粘贴到本地文本编辑器，核对与按钮目标一致。
3. 切换邮件或折叠旧邮件，确认不会复制上一封邮件的链接。
4. 展开带引用的邮件，确认旧链接被排除且有提示。
5. 如需提供兼容性反馈，只记录邮箱服务、客户端语言、是否 iframe、脱敏后的 DOM 结构和错误文案。不要提交真实 token、完整链接或邮件正文。

多链接、伪装域名、复制权限失败等负面场景可在本地测试页与单元测试中验证，无需修改真实邮件。

1.0.1 的回归测试可在本地测试页选择「冒号格式」。更新扩展后先在扩展管理页重新加载，再刷新邮箱，以清除旧版本内容脚本。

弹窗宽度回归：用 100px 的初始视口打开 `extension/popup.html`，根元素与正文仍应为 320px，检测按钮宽 280px、高约 44px，文字不拆行；恢复到 320px 视口后页面应无横向溢出。Chrome 扩展管理页重新加载后，还应检查原生工具栏弹窗的自动尺寸。

1.0.5 的弹窗复制回归使用 `tests/popup-demo.html`：模拟 Chrome 脚本 API，运行生产脚本，检查检测后出现复制按钮、粘贴值与原链接一致、切换邮件阻止旧选择、多链接隐藏复制按钮。所有链接均为虚构凭据；该页面不替代原生扩展 API 和真实邮箱的端到端验证。

1.0.6 还应检查同一测试页中的原邮件：检测前后正文 HTML、黑色登录按钮的尺寸均保持不变，邮件内没有新增 `claude-link-helper` 元素，弹窗复制仍可使用。
